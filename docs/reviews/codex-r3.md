1. **Major — r2 #8 partly fixed.** [`src/SummonFactory.sol:104`](src/SummonFactory.sol:104) limits round/lock terms, and [`:109`](src/SummonFactory.sol:109) permits replacement after a day only when unpledged. The old permanent squat is impossible, and `test_roundsCannotSquatATicker` fails if those term/replacement checks are removed. But an attacker can open a 30-day, unreachable-target round and pledge one raw USDC unit; it is then non-replaceable for 30 days. Worse, replacement only moves factory pointers: an attacker can replace an unpledged round just before a victim’s full pledge lands; the old round still accepts it, but its fill always reverts because [`src/SummonHook.sol:100`](src/SummonHook.sol:100) now recognizes only the replacement. The victim’s funds are stuck until the old deadline/refund. Invalidate/cancel the old round atomically on replacement, make it reject future pledges/auctions, and use a meaningful/slashable opening bond or a replacement rule that can unwind underfunded rounds.

2. **Major — r2 #1 partly fixed.** [`src/SummonFactory.sol:28`](src/SummonFactory.sol:28) makes the direct-Pyth age 5 seconds, and [`src/SummonRound.sol:255`](src/SummonRound.sol:255) requires a post-start publication. `test_pullFeedFillNeedsARecentPrice` fails if the listing’s five-second age is reverted to 60 seconds. It does not eliminate filler price selection: the filler may still choose any favorable post-start Pyth print in that five-second interval. It also harms liveness: a fair fill is impossible until Pyth publishes a strictly post-start price, and then only while it remains under five seconds old—often tighter than RPC, signing, and inclusion latency. Use a committed/keeper first-post-start observation or a deterministic multi-observation settlement rule.

3. **Major — r2 #9 partly fixed.** [`web/worker/store.ts:72`](web/worker/store.ts:72) does keep nonce, rate-limit, and write SQL operations synchronous with no await between check and write. The alarm correctly removes expired intents/counters while retaining nonces ([`:137`](web/worker/store.ts:137)); the cursor query is complete and duplicate-free for a stable dataset ([`:117`](web/worker/store.ts:117)). The named sweep/page tests would fail without deletion/paging.

   However, live intents and permanent nonce rows are unbounded, and every board totals read aggregates all live rows ([`:110`](web/worker/store.ts:110)). A distributed wallet/IP sybil can grow the single global DO indefinitely and serialize all reads and writes. Pagination is also not snapshot-consistent: inserts before the cursor between pages are omitted. A single DO is reasonable for a deliberately small testnet demo, but not as an uncapped public store. Bound retained nonces to the maximum signature lifetime, cap/admit live intents, maintain aggregate rows, and document cursor consistency or issue snapshot tokens.

4. **Major — new: pool swaps ignore the issuer-paused oracle state.** [`src/SummonHook.sol:76`](src/SummonHook.sol:76) checks multiplier and market state but never `Deps.oracleRegistry.getOracleParams(...).paused`, despite the spec requiring `beforeSwap` to use the fill conditions. After a fill, the issuer can set its oracle registry to paused while transfers remain enabled; [`src/SummonRound.sol:465`](src/SummonRound.sol:465) would reject a fill, but traders can still swap against backers’ LP. Check/revert on oracle pause in the hook and add a post-fill oracle-pause swap test.
